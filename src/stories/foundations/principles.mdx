# Aegis design principles

Aegis helps security analysts see what matters, understand the evidence, and act with confidence. Dense event data and AI assistance share a calm, consistent visual language.

## Give the workspace a clear hierarchy

The canvas gives every container breathing room. A surface holds content; a raised surface groups it; a floating surface carries persistent navigation or actions; an overlay presents a focused task. Floating and Fixed use borders and shadows together. Minimalistic uses two neutral surfaces and quieter neutral borders, with no shadows, in both color themes. The examples below show the base light/dark surface tokens.

<SurfaceExamples />

Treat UI approach and light/dark color as independent choices. Floating is the default: navigation and sheets have 12px exterior insets and 12px corners, with 8px corners on the compact navigation rail. Fixed uses full-height chrome against the left and right workspace edges with dividers, square outside corners, and no chrome shadow. Floating and Fixed share color and component styling. Minimalistic adds a distinct presentation with flush chrome, two neutral fills, no shadows, compact corners, and monochrome ordinary controls. All three preserve typography, control heights, content, and interaction state. Navigation is 240px expanded or 48px collapsed, with 12px expanded padding and 12px vertical/6px horizontal collapsed padding. Subtle horizontal dividers separate navigation groups without visible group headings. Its 34px icon rows and top toggle remain stable; labels fade and clip during the fast toggle without wrapping. Panels, charts, dialogs, and sheets use 16px interior padding; cards use 12px. Console pages start with 20px top spacing, reduced to 16px on narrow screens, and related sections use 16px gaps.

In Floating and Fixed, use 10px standard surface corners and 12px large/floating surface corners. Nested surfaces use the shared calculation `12px − 4px = 8px`; apply it to surfaces without changing nested control radii. Corners scale with control height: 28/34/40px buttons use 4/5/6px radii, while inputs and selects retain 6/7/8px. Tags and severity badges use rounded rectangular shapes with 6px corners; checkboxes keep 4px corners. Status badges keep a pill shape in every approach, including Minimalistic. Minimalistic instead uses 4/5/6px control corners, 6px surfaces and avatars, and 4px nested surfaces and chips; chrome remains square, and genuine circular markers retain their shape. These choices preserve density without changing control height or interaction targets.

## Give color a job

Neutral surfaces carry most of the interface. In Floating and Fixed, function blue identifies the next action. Across all three approaches, a magenta-to-pink-to-blue gradient identifies AI assistance across filled, soft, and text treatments. Minimalistic uses monochrome ordinary controls, restrained blue hover and focus feedback, and quieter neutral framing. Red marks destructive actions, green confirms success, and amber calls for attention. Severity is a separate scale: critical, high, medium, low, and informational. Generic tags and severity badges have transparent backgrounds, semantic outlines, and colored dots. Borderless status pills use a restrained 8% semantic tint and a colored dot. All three keep primary theme text in every approach and color theme. Pair color with a label or icon so meaning never depends on color alone.

## Preserve the analyst’s attention

Use Figtree with a 14px interface base and a 13px dense-grid base. Keep timestamps, identifiers, host addresses, and code in JetBrains Mono. Align numeric values with tabular numerals. Grid rows measure 36px in compact density, 48px by default, and 60px in comfortable density. Use compact for rapid scanning and comfortable when secondary context needs room. Long alert titles stay on one line, with the full title available through the tooltip and accessible row label. Keep secondary metadata within the chosen row height. Density preserves the hierarchy and available actions.

Use normal separators for clear boundaries and light separators for quieter grouping. A line divides sections; a dot separates short inline metadata. Both variants inherit semantic theme tokens.

Keep compact breadcrumbs and page actions available from the first scroll on every console page. The title continues underneath the pinned bar.

## Make every path accessible

Every action has a visible label or accessible name. Focus uses the semantic focus token with a 2px ring and 2px offset throughout. Keyboard users can enter and leave menus, navigate trees and grids, and complete dialogs. Restore focus after closing an overlay. Reduced-motion preferences remove decorative animation while preserving clear state changes.

## Guide multi-step work

The console opens rule creation with a vertical stepper so progress stays beside the active task. The reusable wizard also supports a horizontal layout. Keep completed steps revisitable, validate before advancing, and focus the new step heading. A sticky footer holds Back, Continue, and the final action; leaving a dirty workflow requires an explicit choice.

## Keep AI accountable

AI is an explicit intent with a recognizable label and sparkles marker. All three approaches use filled gradients for prominent AI actions, soft gradients for secondary AI controls, and foreground gradients for AI text. Minimalistic keeps generated-content containers neutral and shadow-free while preserving the AI label, evidence, and review controls. Generated content always carries an “AI generated” label. Show the context an assistant can access, link its claims to evidence, and distinguish confidence from certainty.

<AiLanguageExample />

Streaming must leave the interface usable: analysts can stop generation, inspect evidence, or continue working. Describe only work that actually occurred. The local mock says it scoped supplied evidence and prepared verification steps; a production adapter can report query results only after a query runs. Consequential changes require a human decision. Show the current and proposed rule together, provide explicit approve and reject actions, and record who approved the change.

Each assistant turn snapshots its evidence context. New selection cannot change an in-flight response, and regeneration reuses that original snapshot. Stop preserves partial output and returns focus to the composer. Late events from canceled or superseded streams are ignored.

The interactive examples use local, deterministic responses. They illustrate interaction behavior and do not connect to security infrastructure.

## Explore working examples

<FoundationLinks />

The reusable components are available in the `@dimitriszoitas/aegis-ui@0.1.0` package archive. Import `@dimitriszoitas/aegis-ui/styles.css` once alongside the components; it includes compiled styles and tokens, so consumers do not need Tailwind. Optional `reset.css` goes before `styles.css`, and `fonts.css` loads the self-hosted typefaces. Use the `/theme` helpers at the document root so portaled overlays follow the same color and layout settings.

The archive has not been published to the npm registry. Installation, public entry points, and local package verification are documented in the [repository README](https://github.com/dimitriszoitas/aegis-ui#install-the-react-package).
