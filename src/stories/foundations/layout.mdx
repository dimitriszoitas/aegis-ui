# Space and surfaces

Use the same measured rhythm from a filter chip to the complete investigation workspace.

## Layout themes

Floating and Fixed are a layout axis independent of light and dark color. Floating is the default: navigation and sheets have 12px exterior insets, 12px corners, and a floating shadow. The compact navigation rail derives its 8px corners from the same 4px subtraction. Fixed removes those exterior gaps, corner rounding, and chrome shadows. Navigation fills the left edge with a right divider; sheets and the assistant fill the right edge with a left divider.

Both layouts keep the same color tokens, typography, control sizes, card geometry, and content. Use the Storybook layout and color controls to explore all four combinations. The console's Floating layout and Fixed layout examples keep the assistant open for comparison; Alerts lets you switch interactively.

`data-layout-theme` selects the layout independently from `.dark` and `data-theme`. The document attribute also supplies the layout to portaled chrome.

## Surface hierarchy and shadows

Raised surfaces use a subtle border and a small shadow. Floating chrome uses a layered shadow. Overlays use the strongest shadow to establish focus. Dark mode relies more on border contrast and a lighter surface than on shadow strength.

## Radius

Surface corners range from 8–12px; controls retain their compact 6–8px scale. Control radii follow control height within the 6–8px range. Use the component tokens below for buttons, icon buttons, inputs, selects, and other sized controls. Checkboxes keep a 4px radius.

| Control size | Height          | Radius | Token                 |
| ------------ | --------------- | ------ | --------------------- |
| Small        | 28px            | 6px    | `--control-radius-sm` |
| Medium       | 34px            | 7px    | `--control-radius-md` |
| Large        | 40px            | 8px    | `--control-radius-lg` |
| Checkbox     | Compact control | 4px    | `--control-radius-xs` |

<ControlRadiusExamples />

Standard cards and charts use `--surface-radius` (10px). Large or floating surfaces use `--surface-radius-floating` (12px). Nested surface components use `--surface-radius-nested`: `calc(var(--surface-radius-floating) - var(--space-1))`, so a 12px parent and a 4px inset step produce 8px child corners. Use this shared relationship rather than independent corner values. It applies to surface components, never to nested controls.

Fixed chrome uses square outside corners while cards retain the same 10/12/8px geometry in both layouts. The navigation toggle stays at the top in both states. Chips and badges remain rounded rectangles with 6px corners from `--chip-radius`.

<SurfaceRadiusExamples />

The control primitive scale remains 6px for `xs` and `sm`, 7px for `md`, and 8px for `lg`, `xl`, and `2xl`. The legacy `--radius-full` token is also capped at 8px. Small dots can still appear circular because their dimensions constrain the rendered curve. Values below come from the shared primitive scale.

## Spacing

The spacing scale uses a 4px base. Floating chrome has a 12px exterior inset; Fixed chrome has none. Panels, charts, dialogs, and sheets use 16px interior padding; cards use 12px. Grid cell padding follows density: 3px vertically in compact rows, 8px by default, and 10px in comfortable rows.

<SpacingExamples />

Nested content advances by a small 12px step using `--nested-inset`. Use it for accordion bodies, navigation children, tree levels, JSON branches, and expanded table content so parent and child items remain easy to follow.

## Data density

Use the component row-height tokens: `--grid-row-compact` is 36px, `--grid-row-default` is 48px, and `--grid-row-comfortable` is 60px. Expanded evidence is measured separately, so changing density does not clip nested payloads. Truncate long primary labels within the row and expose the full value through a tooltip or accessible label.

## Scrollbars

Overflowing pages and nested regions share native scrollbar styling in both themes. Where custom scrollbar styling is supported, an 8px transparent track contains a 6px thumb with a 1px inset and 4px corners. The thumb uses the strong border color, secondary text color on hover, and primary text color while active.

Browsers using the standards fallback render a thin scrollbar. Forced-colors mode retains native styling. Scrollbar visibility follows content overflow and browser or operating-system preferences; content that fits does not need one. Keyboard, wheel, touch, and native scroll behavior remain unchanged.

## Separators

Use a line between sections or controls, and a dot between short inline metadata values. Both variants support `normal` and `light` emphasis. Lines use default or subtle border tokens. Dots use secondary text or strong border tokens to remain visible at their smaller size. Choose emphasis by how much separation the surrounding content needs.

## Workflow layout

The detection-rule wizard supports a horizontal stepper and a vertical rail. The console defaults to the vertical layout; at narrow widths the rail stacks above the active step. Use the sticky footer to keep navigation and explicit approval within reach.

## Layer order

Sticky content sits at 40, dropdowns at 50, sheets at 60, modals at 70, popovers at 80, toasts at 90, and tooltips at 100. Consume the named z-index tokens so nested interactions remain predictable.
